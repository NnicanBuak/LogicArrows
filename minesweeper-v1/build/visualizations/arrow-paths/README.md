# Настоящая разводка ячейки: 25 изображений

[PDF: все 25 листов с закладками](../../../output/pdf/minesweeper-cell-arrow-paths.pdf).

Каждый лист содержит стрелки из **архивного сохранения 56×64 с 2 424 стрелками**
(SHA-256 `b2d7f378272115992b12529730fc302a67196c8808673d891c4e35476ee714f7`).
Координаты, типы, повороты и зеркальность сохранены. Текущая разводка после
оптимизации кнопки и выходов ворот отличается; этот архив не перерисован.
Подсвечены только пути к выбранным вычислителям; остальные стрелки приглушены.
Цвет подложки различает сигналы. Чёрная рамка отмечает вычислитель; пунктир связывает подпись с его настоящей стрелкой.

| Изображение | Что проследить |
|---|---|
| [01 · Кнопка: настоящая разводка до request](01-button-request.png) | Подсвечены 25 кнопок, их сборка и путь button0. NOT busy разрешает запись запроса в SET; обе копии n5 видны на входах памяти. |
| [02 · Как проводка выбирает первый ход](02-select.png) | request и отсутствие более раннего W:prefixReq выбирают клетку. Прямой и инверсный пути choose создают короткий импульс записи selected. |
| [03 · Защита 3×3 и проводка генерации](03-generate.png) | Пять входов NOR защищают старт и соседей. Вне защиты импульс sample проходит два RANDOM и сохраняет mine в TFF. |
| [04 · Исходящие мины: мои данные соседям](04-send-mines.png) | N:M + mine + S:M образуют мою вертикальную тройку. XOR/MAJ дают биты MP/MC для W/E; на N/S отправляется только mine. |
| [05 · Входящие мины: сложить соседние тройки](05-receive-count.png) | Здесь видны именно входящие W/E:MP/MC и N/S:M. Они складываются; собственная mine в сумму не входит. Чёрные рамки отмечают суммы и переносы. |
| [06 · Реальная разводка переносов](06-carries.png) | n47 и n48 имеют вес 2; n49 — вес 4. Два полусумматора дают старшие биты 2/4/8. Младший бит n51 уже готов на листе 05. |

| [12 · Только prefixReq: действующий скан запросов](12-scan-request.png) | W:prefixReq OR request → E:prefixReq. Этот путь используется при выборе первого хода: см. W:prefixReq на листе 02. |
