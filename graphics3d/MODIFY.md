## Заменить компактную модель

В качестве основы возьмите [готовую программу куба](compact/models/cube/graphics3d.asm). Её вычислительная часть совпадает с [общим движком](compact/engine.asm); модель начинается с метки `model` в банке 7, по физическому смещению **896**.

1. Опишите вершины в координатах относительно центра фигуры.
2. Умножьте координаты на два: записи `X₂,Y₂,Z₂` измеряются в половинах единицы.
3. Укажите число вершин V и рёбер E в двухбайтовом заголовке.
4. Запишите V троек координат и E пар байтов рёбер подряд.
5. Замените всю секцию геометрии исходника, оставив вычислительный код перед ней.

Индексы начинаются с нуля. Запись ребра — пара индексов `a,b`. Например, ребро от вершины 1 к вершине 2 кодируется парой **1,2**. Цвет выбирает движок по порядку рёбер: синий → красный → синий.

Для треугольного каркаса с вершинами $(−4,−4,0)$, $(4,−4,0)$, $(0,4,0)$ секция выглядит так:

```asm
model       db 3,3
model_v0    db 248,248,0
model_v1    db 8,248,0
model_v2    db 0,8,0
model_edge0 db 0,1          ; Ребро 0 → 1
model_edge1 db 1,2          ; Ребро 1 → 2
model_edge2 db 2,0          ; Ребро 2 → 0
```

В этом формате 248 представляет −8, что соответствует −4 единицам модели. Каждая строка данных начинается с метки и `db`; записи размещаются последовательно.

Геометрия занимает `2 + 3V + 2E` байт. В примере это **17 байт**, вместе с общим кодом — **913 байт**. Секция модели помещается в один 128-байтовый банк. Размер выбирается так, чтобы все проекции при вращении и масштабе ×2 оставались внутри 16×16; готовые демонстрации используют координаты `X₂,Y₂,Z₂` в пределах −15…15.

Уменьшайте координаты равномерно относительно центра, пока для всех 32 углов суммы `X₂ × C + Z₂ × S` и `Z₂ × C − X₂ × S` помещаются в −127…127, а обе экранные координаты — в 0…15. Коэффициенты и точные формулы приведены в [описании проекции](README.md#проекция-и-кадр).

## Заменить модель полного API

Возьмите [готовое приложение куба](build/cube/graphics3d.asm) или [демонстрацию команд](build/controls/graphics3d.asm). Они содержат общий [engine.asm](engine.asm), рабочую область, геометрию и приложение.

Модель начинается с `model_data` по адресу **`MODEL_BASE:MODEL_ADDR`**:

| Часть | Данные |
|---|---|
| Заголовок | `V,E,T` |
| Вершины | V троек `X,Y,Z` |
| Рёбра | E троек `a,b,color` |
| Полигоны | T четвёрок `a,b,c,color` |

Все полные режимы используют этот формат. Координаты — знаковые целые байты; **252 означает −4**. Индексы вершин начинаются с нуля.

Один красный полигон:

```asm
model_data db 3,0,1
model_v0   db 252,252,0
model_v1   db 4,252,0
model_v2   db 0,4,0
model_tri0 db 0,2,1,1
```

Геометрия занимает **16 байт**, её рабочая область — **17 байт**: `4×3 + 5×1`. Режим `RENDER_POLYGONS` выбирает заполнение. Для каркасного изображения добавьте записи рёбер и выберите `RENDER_WIREFRAME`. Модель может содержать оба списка для переключения режимов во время работы.

### Разместить выросшие данные

В готовых программах рабочие массивы и модель идут подряд, начиная с `VERTEX_BASE:128`. Для смещения q от этого начала:

```text
bank(q) = VERTEX_BASE + floor(q / 128)
addr(q) = 128 + (q mod 128)

Экранные вершины: q = 0,       длина 4V
Рабочие полигоны: q = 4V,  длина 5T
Модель: q = 4V + 5T,          длина S = 3 + 3V + 3E + 4T
Приложение: следующий банк после конца модели
```

При замене геометрии:

1. Выделите `4V` байт под `projected_vertices` и `5T` байт под `triangle_cache`.
2. Разместите `model_data` следом за массивами и обновите `MODEL_BASE/MODEL_ADDR`.
3. Установите границу рабочего буфера перед `model_data`: передайте её через `out_bank/out_addr` в `gfx_set_workspace`.
4. Передайте начало геометрии через `ptr_bank/ptr_addr` в `gfx_load_model`. Проверьте A: успешная привязка возвращает 1.
5. Дополните данные до границы банка и разместите приложение. Задайте `APP_BANK` равным банку метки `main`.

Для куба $V=8$, $E=12$, $T=12$. Рабочая область занимает $4\cdot8+5\cdot12=92$ байта. Модель начинается по адресу **220** банка `VERTEX_BASE` и занимает **111 байт**. Её конец лежит по адресу **203** следующего банка; приложение начинается в следующем после него банке.

Подпрограммы и константы общего модуля сохраняют своё расположение. В готовых приложениях `MAX_VERTICES/MAX_TRIANGLES` обозначают размеры выделенных массивов; фактические счётчики движок читает из заголовка модели.

При размещении нескольких записей геометрии в памяти выделите рабочую область по максимальным V и T. Вызов `gfx_load_model` выбирает одну запись как активный объект. Углы, масштаб и положение относятся к выбранной геометрии.

## Выбрать проекцию и примитивы

Приложение вызывает подпрограммы с параметром A:

| Подпрограмма | Значения |
|---|---|
| `gfx_set_projection` | `PROJECTION_PERSPECTIVE`, `PROJECTION_PARALLEL` |
| `gfx_set_render_mode` | `RENDER_WIREFRAME`, `RENDER_POLYGONS`, `RENDER_BOTH` |
| `gfx_set_cull` | 0 — обе стороны, 1 — передние полигоны |

Например, параллельная проекция:

```asm
ldi a, PROJECTION_PARALLEL
ld c, 0x3F
st c, ret1_bank
ldi d, projection_ready
st d, ret1_addr
ldi c, GFX_SET_PROJECTION_BANK
ldi d, gfx_set_projection
jmp set_bank

projection_ready:
                           ; Следующий кадр получит этот режим
```

Эта схема применяется ко всем командам со слотом 1. Для команды привязки или рисования используется слот 0. Полная таблица приведена в [API.md](API.md#подпрограммы).

## Изменить цвета

| Номер | Цвет |
|---:|---|
| 0 | Белый для пикселей и заливки, прозрачный для линии |
| 1 | Красный |
| 2 | Синий |
| 3 | Фиолетовый |

Полный API предоставляет три способа:

- `COLOR_MODEL`: измените последний байт записи `a,b,color` или `a,b,c,color`.
- `COLOR_ALTERNATING`: движок назначает синий и красный по порядку рёбер, затем полигонов.
- `COLOR_SOLID`: задайте общий цвет вызовом `gfx_set_color`.

Способ выбирается вызовом `gfx_set_color_mode`. Параметры сохраняются в состоянии объекта. При прямом вызове `gfx_line`, `gfx_pixel` или `gfx_triangle` установите переменную `color`.

Линии объединяют цветовые биты операцией OR. Красный и синий дают фиолетовый на пересечении. Пиксели и заполненные полигоны записывают выбранный цвет в оба слоя.

Прямые вызовы примитивов размещайте **между `gfx_begin` и `gfx_present`**. Они меняют LCD RAM `0x40…0x7F` при отключённом обновлении дисплея. После построения кадра `gfx_present` включает вывод и повторно записывает те же 64 байта. Рабочие данные заливки `TRI_STATE_BANK:TRI_STATE0` занимают 12 байт и остаются отдельными от изображения.

Компактная модель хранит пары индексов рёбер. Последовательность синего и красного задаётся циклом `edge_begin` её движка.

## Изменить вращение, масштаб и положение

### Полный API

| Действие | Команда | Параметры |
|---|---|---|
| Задать углы | `gfx_set_rotation` | `wx/wy/wz`: Y/X/Z, 0…31 |
| Добавить поворот | `gfx_rotate` | `wx/wy/wz`: знаковые приращения Y/X/Z |
| Задать масштаб | `gfx_set_scale` | A: 32 — ×1, 48 — ×1,5, 64 — ×2 |
| Задать положение | `gfx_set_position` | `wx/wy/wz`: X/Y/Z |
| Переместить объект | `gfx_move` | `wx/wy/wz`: знаковые смещения X/Y/Z |

Один угловой шаг равен **11,25°**. Значения 0, 8, 16 и 24 соответствуют 0°, 90°, 180° и 270°. Порядок преобразований: масштаб, вращение Y/X/Z, смещение, проекция.

Для постоянного ракурса установите углы один раз при подготовке объекта. Для движения вызывайте относительные команды перед следующим `gfx_draw_object`. Команды обновляют сохранённое состояние; построение кадра использует исходные вершины модели.

Пример поворота вокруг Y на один шаг:

```asm
ldi a, 1
st a, wx
clr a
st a, wy
st a, wz
ld c, 0x3F
st c, ret1_bank
ldi d, rotation_ready
st d, ret1_addr
ldi c, GFX_ROTATE_BANK
ldi d, gfx_rotate
jmp set_bank

rotation_ready:
                           ; Следующая отрисовка использует новый угол
```

Готовые анимации задают абсолютные углы в `frame_start` и масштаб в `frame_scale`. Для собственного управления разместите вызовы команд в приложении перед `frame_draw`. [Демонстрация команд](build/controls/graphics3d.asm) также обновляет положение и режимы в `frame_controls`.

### Компактная программа

`phase` задаёт поворот вокруг Y, `pulse_phase` — фазу пульсации, `scale` — коэффициент **64…128**, соответствующий ×1…×2.

Для постоянного угла замените увеличение `phase` в `frame_presented` записью выбранного индекса 0…31. Установите тот же индекс в первом байте `globals`.

Для постоянного размера замените расчёт в `pulse_update` записью **64** для ×1, **96** для ×1,5 или **128** для ×2. Сохраните переход к `frame_start`. Начальный масштаб хранится в `globals` под индексом **31**, считая от нуля.

Компактный код размещён в 128-байтовых банках. При замене участка сохраняйте адреса следующих секций, дополняя банк директивой `db`.

## Подготовить заполненные грани

Для замкнутой фигуры задайте обход полигонов наружу. Вызов `gfx_set_cull` с A=1 включает отбрасывание обратных граней. Внешние поверхности рисуются от дальних к ближним. A=0 выбирает обе стороны.

Направление обхода разобрано в [теоретической части](README.md#какие-поверхности-видны). Схема вызова режима и примитивов дана в [ASM API](API.md).

## Изменить куб Cube16

Отдельная [монохромная программа Cube16](compact/cube16.asm) занимает **1022 байта**. Её вершины вычисляются по индексам, а соединения задаёт таблица `edges`.

| Параметр | Место в ASM |
|---|---|
| Высота | `vertex_calc`, значение 3 перед меткой `y_positive` |
| Направление вращения | `frame_complete`, обновление `phase` |
| Размер по горизонтали | Амплитуда 32 значений таблицы `sine` |
| Соединение вершин | Двенадцать пар индексов в таблице `edges` |

Кадр строится в 32-байтовом буфере `0x60…0x7F` и переносится на монохромный дисплей `0x40…0x5F`. Режим дисплея включается значением `0x10` в порту `0x3E`. Эта программа использует постоянный масштаб; общий цикл пульсации описан для цветных демонстраций в [README.md](README.md#анимация).
