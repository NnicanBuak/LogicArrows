# 3DGraphics: справочник ASM API

Полный движок хранит состояние **одного активного объекта**: указатель на геометрию, три угла, масштаб и положение. Команды изменяют это состояние; построение кадра читает исходные вершины модели и применяет выбранные преобразования.

## Подготовка объекта и кадра

1. Выделите рабочую область от `VERTEX_BASE:128` длиной `4V + 5T` байт.
2. Передайте её конец через `out_bank/out_addr` в `gfx_set_workspace`. Конечный адрес — первый байт за областью.
3. Передайте указатель на модель через `ptr_bank/ptr_addr` в `gfx_load_model`. Результат A=1 означает успешную привязку.
4. Задайте вращение, масштаб, положение и режимы вызовами `gfx_set_*`.
5. Постройте кадр: **`gfx_begin` → `gfx_draw_object` → `gfx_present`**.

Привязка сохраняет указатель на одну модель. Следующая успешная привязка выбирает новую геометрию для того же состояния объекта. `gfx_draw_object` восстанавливает указатель перед чтением каждого кадра. Углы, масштаб, положение и режимы сохраняются между вызовами.

`gfx_set_workspace` сбрасывает активность. После изменения границы снова вызовите `gfx_load_model`. Эта команда проверяет число вершин и вместимость рабочих массивов; при ошибке возвращает A=0 и оставляет объект неактивным. В таком состоянии вызов рисования завершает работу сразу.

## Подпрограммы

| Подпрограмма | Аргументы | Результат | Слот N | Константа банка |
|---|---|---|---:|---|
| `gfx_set_workspace` | `out_bank/out_addr`: конец рабочего буфера | Сохранена граница, активность сброшена | 1 | `GFX_SET_WORKSPACE_BANK` |
| `gfx_load_model` | `ptr_bank/ptr_addr`: начало модели | Привязан один объект; A=1 — готов, A=0 — ошибка | 0 | `GFX_LOAD_MODEL_BANK` |
| `gfx_set_rotation` | `wx/wy/wz`: углы Y/X/Z | Установлены абсолютные углы | 1 | `GFX_SET_ROTATION_BANK` |
| `gfx_rotate` | `wx/wy/wz`: знаковые приращения углов Y/X/Z | Обновлены углы по модулю 32 | 1 | `GFX_ROTATE_BANK` |
| `gfx_set_scale` | A: масштаб Q5 | Обновлён `STATE_SCALE` | 1 | `GFX_SET_SCALE_BANK` |
| `gfx_set_position` | `wx/wy/wz`: положение X/Y/Z | Установлено положение объекта | 1 | `GFX_SET_POSITION_BANK` |
| `gfx_move` | `wx/wy/wz`: знаковые смещения X/Y/Z | Обновлено положение объекта | 1 | `GFX_MOVE_BANK` |
| `gfx_set_projection` | A: 0 — перспектива, 1 — параллельная | Обновлён режим проекции | 1 | `GFX_SET_PROJECTION_BANK` |
| `gfx_set_render_mode` | A: 1 — рёбра, 2 — заливка, 3 — оба | Обновлён набор рисуемых примитивов | 1 | `GFX_SET_RENDER_MODE_BANK` |
| `gfx_set_color_mode` | A: 0 — модель, 1 — чередование, 2 — единый цвет | Обновлён способ выбора цвета | 1 | `GFX_SET_COLOR_MODE_BANK` |
| `gfx_set_color` | A: номер цвета 0…3 | Задан цвет режима `COLOR_SOLID` | 1 | `GFX_SET_COLOR_BANK` |
| `gfx_set_cull` | A: 0 — обе стороны, 1 — передние грани | Обновлён режим отсечения | 1 | `GFX_SET_CULL_BANK` |
| `gfx_begin` | — | Вывод отключён, оба слоя LCD RAM очищены | 0 | `GFX_BEGIN_BANK` |
| `gfx_draw_object` | Сохранённая модель и параметры объекта | Объект нарисован в LCD RAM | 0 | `GFX_DRAW_OBJECT_BANK` |
| `gfx_draw_mesh` | Сохранённая модель и параметры объекта | Второе имя `gfx_draw_object` | 0 | `GFX_DRAW_MESH_BANK` |
| `gfx_present` | — | Вывод включён, 64 байта LCD RAM повторно записаны | 0 | `GFX_PRESENT_BANK` |
| `gfx_scale_vertex` | `wx/wy/wz`: XYZ, `STATE_SCALE` | Масштабированные XYZ | 1 | `GFX_SCALE_VERTEX_BANK` |
| `gfx_rotate_pair` | `ru/rv`, `angle` | Повернутая пара `ru/rv` | 2 | `GFX_ROTATE_PAIR_BANK` |
| `gfx_project_vertex` | `wx/wy/wz`: масштабированные XYZ | `wx/wy`: экран; `wz`: видимость; `depth`: глубина | 1 | `GFX_PROJECT_VERTEX_BANK` |
| `gfx_get_vertex` | A: индекс экранной вершины | `wx/wy/wz/depth` из буфера | 1 | `GFX_GET_VERTEX_BANK` |
| `gfx_pixel` | `wx/wy`, `color` | Записан пиксель | 2 | `GFX_PIXEL_BANK` |
| `gfx_line` | `x0/y0`, `x1/y1`, `color` | Нарисован отрезок | 1 | `GFX_LINE_BANK` |
| `gfx_triangle` | `x0/y0`, `x1/y1`, `dx/dy`: третья точка, `color` | Заполнен полигон | 1 | `GFX_TRIANGLE_BANK` |

Константы `GFX_*_BANK` и метки подпрограмм определены в [engine.asm](engine.asm). Полные демонстрации содержат одинаковый модуль библиотеки. Их приложения выбирают начальные режимы через вызовы API.

Приложение объявляет `APP_BANK` и метку `main`, размещает общий модуль в начале исходника и выделяет память для рабочих массивов и модели. Начальный переход передаёт управление в `APP_BANK:main`. Счётчик кадров, обновление углов и пульсация масштаба задаются кодом приложения.

## Передача управления

Слот N из таблицы определяет пару `retN_bank/retN_addr`. Сохраните текущий банк и адрес продолжения, затем передайте банк подпрограммы в C, метку входа в D и перейдите в `set_bank`.

Установка параллельной проекции:

```asm
ldi a, PROJECTION_PARALLEL
ld c, 0x3F
st c, ret1_bank
ldi d, projection_ready
st d, ret1_addr
ldi c, GFX_SET_PROJECTION_BANK
ldi d, gfx_set_projection
jmp set_bank

projection_ready:
                           ; Продолжение приложения
```

Регистры и рабочие переменные изменяются при вызове. Аргументы следующей команды задаются заново. `depth` и `angle` занимают одну рабочую ячейку; глубину считывают сразу после получения вершины.

## Преобразования объекта

| Команда | Параметры |
|---|---|
| `gfx_set_rotation` | `wx` — Y, `wy` — X, `wz` — Z; углы 0…31, шаг 11,25° |
| `gfx_rotate` | Знаковые приращения тех же трёх углов |
| `gfx_set_scale` | A: 32 — ×1, 48 — ×1,5, 64 — ×2 |
| `gfx_set_position` | `wx/wy/wz` — X/Y/Z центра объекта в единицах модели |
| `gfx_move` | Знаковые приращения положения X/Y/Z |

Порядок преобразований: **масштаб → вращение Y/X/Z → смещение → проекция**. Углы и положение относятся ко всему активному объекту. Данные геометрии служат исходной системой координат для каждого кадра.

Положительный X направлен вправо, положительный Y — вверх, положительный Z — от камеры. Смещение добавляется после вращения, поэтому оно задаётся вдоль осей пространства.

## Режимы во время работы

| Настройка | Значения A |
|---|---|
| `gfx_set_projection` | `PROJECTION_PERSPECTIVE=0`, `PROJECTION_PARALLEL=1` |
| `gfx_set_render_mode` | `RENDER_WIREFRAME=1`, `RENDER_POLYGONS=2`, `RENDER_BOTH=3`; 0 пропускает оба вида примитивов |
| `gfx_set_color_mode` | `COLOR_MODEL=0`, `COLOR_ALTERNATING=1`, `COLOR_SOLID=2` |
| `gfx_set_color` | 0 — белый, 1 — красный, 2 — синий, 3 — фиолетовый |
| `gfx_set_cull` | 0 — обе стороны, 1 — передние полигоны |

`COLOR_MODEL` берёт цвет из записи примитива. `COLOR_ALTERNATING` назначает последовательность 2, 1, 2, 1… по порядку рёбер, затем полигонов. Последовательность начинается с синего при каждом рисовании объекта. `COLOR_SOLID` использует цвет, заданный `gfx_set_color`.

Рёбра обрабатываются перед полигонами. Заливка сортируется по сумме глубин от дальних поверхностей к ближним. Отсечение выбирает полигоны с положительной экранной площадью. Прямой вызов `gfx_triangle` заполняет оба направления обхода.

`gfx_line` объединяет цветовые биты операцией OR. Пересечение красной и синей линий получается фиолетовым. Цвет 0 линии прозрачен. `gfx_pixel` и `gfx_triangle` записывают заданный цвет в оба слоя. Прямые вызовы примитивов получают цвет через переменную `color`.

## Формат модели и память

Модель содержит заголовок **`V,E,T`**, затем `3V` байт координат XYZ, `3E` байт рёбер `a,b,color` и `4T` байт полигонов `a,b,c,color`. Индексы начинаются с нуля. Координаты — знаковые байты; `252` означает −4.

Объём геометрии равен `3 + 3V + 3E + 4T`. Модель может содержать рёбра и полигоны одновременно. Режим отрисовки выбирает примитивы из этих списков.

Рабочая область начинается с `VERTEX_BASE:128`. Экранные вершины занимают `4V` байт в формате `x,y,visible,depth`. Следом находятся `5T` байт рабочих полигонов. Их начало движок определяет из числа вершин. Граница области задаётся `gfx_set_workspace`.

Состояние находится в `STATE_BANK`. Координаты положения хранят `STATE_TX/TY/TZ`; режимы — `STATE_PROJECTION`, `STATE_RENDER`, `STATE_COLOR_MODE`, `STATE_COLOR`, `STATE_CULL`. Указатель активной модели — `STATE_MODEL_BANK/ADDR`, признак готовности — `STATE_ACTIVE`. Маски синуса `LUT_BASE:LUT_ADDR` занимают **28 байт**.

Экранные координаты: 0…15, X вправо, Y вниз. Красный слой LCD RAM — `0x40…0x5F`, синий — `0x60…0x7F`; эта память доступна из любого банка. Банк выбирается через `0x3F`.

**Отдельного кадрового буфера нет.** `gfx_begin` записывает 0 в порт `0x3E`, отключая обновление дисплея, и очищает оба слоя LCD RAM. Примитивы рисуются прямо в них; дисплей сохраняет предыдущую картинку. `gfx_present` включает цветной режим значением `0x30` и повторяет запись каждого готового байта по тому же адресу: `ld a, b` → `st a, b`. Вывод последовательный. Вызовы рисования размещайте между `gfx_begin` и `gfx_present`.

Определители рёбер и приращения заливки занимают **12 байт `TRI_STATE_BANK:TRI_STATE0`**. Они сохраняются как рабочие данные треугольника.

Полные демонстрации занимают **5106…5503 байта (>1 КБ)**. Компактный движок использует формат `V,E`, вращение вокруг Y и встроенный цикл пульсации; его устройство описано в [README.md](README.md#компактный-каркасный-движок).
